Where the criteria come from

    
Each criterion maps to an interface pattern with a positive and a negative case. Evidence comes from the existing pattern library and UI teardowns (UX_for_AI_RITE, BiasGuard's risk matrix). Repeatable checks, not opinions.

  

  

    
How evidence plugs back

    
Each run writes a record with build hash and per-criterion results. It hangs under the existing PIA / Model Card on the governance platform — the UI-level evidence cell. Gate and replay follow the HITL Proxy Auditor.

  

  

    
Why a third party

    
Clause E sits on the Shielk boundary: de-identification itself creates a trust problem. The user cannot see what was masked, and has no remedy if the mask is wrong. The data layer cannot answer that. The document layer should not.
